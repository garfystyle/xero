## Установка

**VS Code** — этого достаточно, Java не нужна.

1. Скачай `xero-0.1.5-beta.vsix` со [страницы релиза](https://github.com/garfystyle/xero/releases/tag/v0.1.5-beta).
2. VS Code → Расширения → `···` → **Установить из VSIX…**

**Терминал** — по желанию, нужна Java 25.

1. Скачай `xero-0.1.5-beta.zip` оттуда же и распакуй.
2. Добавь папку `bin` в `PATH`.

**Мод [XeroCode](https://github.com/garfystyle/xerocode)** — по желанию: код уходит в игру сам, без команды в чате.

**Из исходников** — нужны JDK 25 и Node.js.

```bash
./gradlew :js:vsix            # расширение → js/build/dist/
./gradlew :cli:installDist    # терминал → cli/build/install/xero/
```

## Быстрый старт

1. В VS Code создай файл `main.xero`:

   ```kotlin
   when player_join {
       send_message("Привет, %player%!")
   }
   ```

2. В игре зайди в свой мир в `/dev`.
3. Вернись в **VS Code**, нажми там `Ctrl+Shift+P` и выбери **Xero: Залить в мир**.
4. Вставь команду из буфера обмена в чат игры в течение 60 секунд. С модом XeroCode код уйдёт сам.
5. Выйди в игру через `/play`: сообщение придёт при входе.

> ⚠️ `Ctrl+Shift+P` нажимай в VS Code, а не в игре: в моде XeroCode это «Перезапустить мир».

> ⚠️ **Залить в мир** заменяет код мира проектом. Чтобы только добавить код — **Дописать в мир**. Подробнее — [Заливка в мир](#заливка-в-мир).

> 💡 Имена помнить не нужно: начни писать `отправ` — VS Code предложит `send_message`. В терминале — `xero find сообщ`.

## Синтаксис

### Основа

- Файл `.xero`, UTF-8. Блоки — в `{ }`, `;` не нужна, внутри скобок строку можно переносить.
- Комментарии: `//` и `/* */`.
- Код — только внутри `when`, `func` и `process`. Снаружи — `const`, `import` и объявления областей.
- Имя с пробелами или совпавшее со словом языка — в обратных кавычках: `` `монеты %player%` ``.

Слова языка пишутся по-английски и по-русски:

| | | | | |
|:--|:--|:--|:--|:--|
| `when` когда | `func` функция | `process` процесс | `start` запустить | `import` импорт |
| `if` если | `else` иначе | `not` не | `and` и | `or` или |
| `for` для | `in` в | `step` шаг | `while` пока | `repeat` повторить |
| `forever` всегда | `break` прервать | `continue` продолжить | `return` вернуть | `const` константа |

### События

```kotlin
when player_join {
    send_message("Привет, %player%!")
}
```

Имя события — id сервера, список — в [справочнике](docs/events.md). Строки встают в мир в порядке файла. `return` в `when` и `process` заканчивает срабатывание.

### Функции

```kotlin
func kit(amount: number = 1) {
    give_items(item(diamond), amount)
}

func plus(a, b) {
    return a + b
}

when player_join {
    kit()
    kit(amount: 5)
    s = plus(2, 3)
    send_message("Итого ${plus(s, 1)}")
    if plus(s, 1) > 5 {
        kit(2)
    }
}
```

- Параметр: `имя`, `имя: вид`, `имя = умолчание`. Без умолчания — обязательный. `= _` — необязательный без значения.
- Виды: `any` `text` `number` `location` `vector` `block` `item` `sound` `particle` `potion` `array` `map` `variable`.
- Маркер: `mode: enum("alpha", "beta") = "beta"`. В вызове — вариант текстом, словом или переменная.
- Описание для сундука вызова — строка после вида: `amount: number "Сколько выдать" = 1`.
- Несколько значений в одном параметре — вид и число клеток: `lines: text[3]`. В вызове — списком: `f(["a", _, "c"])`.
- Имя с пробелами — в обратных кавычках: `` `Список вещей`: array ``.
- Вызов — по порядку или по имени. Функция с результатом пишется везде, где нужно значение.
- Аргумент считается до вызова: `f(x + 1)`, `f("t${x}")`, `f("%player%")` передают готовое значение. Значение по умолчанию тоже бывает формулой: `func f(a, b = a + 1)`.
- Список и словарь передаются по ссылке: функция меняет их и снаружи. Копия — `k = l`. Параметр вида `variable` — ссылка на саму переменную.
- Имя с точкой пишется как есть: `func Mapi.load() { }`. Функция из мира, которой нет в файле, — в обратных кавычках: `` `WE Load`(region: "a") ``.
- Функция, названная как действие, пишется в обратных кавычках: `` func `wait`() { } ``. Обычный `wait(1)` при этом остаётся действием.

Подпись любой длины можно разбить на строки:

```kotlin
func announce(
    title: text "Заголовок",
    lines: text[3] "Строки сообщения",
    `Задержка показа`: number "В тиках" = 0,
) {
    wait(`Задержка показа`)
    send_message(title)
    send_message(lines)
}

when player_join {
    announce("Новости", ["раз", "два"])
}
```

Функция может вызывать сама себя, параметры и `line` у каждого вызова свои:

```kotlin
func fact(n: number) {
    if n <= 1 {
        return 1
    }
    return n * fact(n - 1)
}

when player_join {
    send_message("5! = ${fact(5)}")
}
```

> ⚠️ Локальные переменные у функции общие с вызывающим кодом: `n = 5` внутри функции меняет `n` снаружи. Компилятор предупреждает об этом. Своё имя держи в `line`.

### Процессы

```kotlin
process timer() {
    forever {
        wait(20)
    }
}

when world_start {
    start timer()
}
```

Процесс идёт отдельно и значения не возвращает. Настройки запуска:

| Настройка | Варианты |
|:--|:--|
| `local_variables_mode` | `dont_copy` свои локальные · `copy` копия · `share` общие |
| `target_mode` | `current_target` · `current_selection` · `no_target` · `for_each_in_selection` |

### Действия

Имя действия — id сервера без приставки: `player_send_message` → `send_message`. Если имя есть в нескольких категориях, оно пишется с категорией: `player.teleport`, `var.value`.

Категории: `player` `entity` `game` `var` `select` `repeat` `control` `controller`.

```kotlin
when player_join {
    send_message("Привет")
    give_items([item(diamond, 5), item(stick)])
    player.teleport(loc(0, 64, 0))
    wait(1, time_unit: seconds)
    n = get_list_length([1, 2, 3])
}
```

- Аргументы — по порядку или по имени. Маркер — словом или по имени: `wait(1, seconds)`, `wait(1, time_unit: seconds)`.
- У 12 действий порядок аргументов не такой, как у сервера: `remove_text`, `get_map_value`, `replace_items`, `replace_container_items`,
  `replace_blocks_in_region`, `spawn_mob`, `spawn_armor_stand`, `spawn_effect_cloud`, `ray_trace_result`, `set_item_placeable_blocks`,
  `set_item_destroyable_blocks`, `add_custom_crafting_recipe`. Их удобнее писать по имени: `remove_text(text: t, remove: "b")`. По
  порядку они собираются, как раньше, а код из мира печатается с именами.
- Несколько значений — списком. Лишнее сверх ёмкости — ошибка.
- `x = действие(…)` записывает результат в `x`. Если первым передана переменная и значение меняется в ней, `x =` можно не писать: `set_item_lore(x, "текст")` — то же, что `x = set_item_lore(x, "текст")`.
- `_` — пустая клетка. Хвост сетки дополняется сам, но посреди сетки без `_` предметы съедут:

```kotlin
when world_start {
    add_custom_crafting_recipe(name: "ruby_sword", result: item(diamond_sword), items: [
        _, item(emerald), _,
        _, item(emerald), _,
        _, item(stick),   _,
    ], recipe_type: shaped)
}
```

Все 1000+ действий — в [справочнике](docs/actions/README.md).

### Цели

`@цель` пишется перед действием, условием или игровым значением:

```kotlin
when player_kill_player {
    @killer give_items(item(emerald))
    if @victim has_item(item(totem_of_undying)) {
        @all send_message("Тотем!")
    }
    x = @killer value.current_health
}
```

| Кто | Цели |
|:--|:--|
| Игрок | `@current` `@default` `@killer` `@damager` `@shooter` `@victim` `@random` `@all` |
| Сущность | то же, а ещё `@projectile` `@all_mobs` `@last` |

Цель работает и внутри формулы или подстановки: `x = @killer value.current_health + 1`, `"хп ${@current value.current_health}"`. Значение сначала записывается в переменную отдельным блоком.

> ⚠️ В событии мира игрока по умолчанию нет: действие над игроком без цели никому не дойдёт. Пиши `@all`.

> ⚠️ В условии выборки сущностей `@current value.x` смотрит не на кандидата, и компилятор об этом предупреждает. Используй условие цели: `entity.name_equals("моб")`.

### Значения

| Запись | Вид |
|:--|:--|
| `"текст"` | текст, цвета через `&` |
| `mm"<red>текст"` `plain"…"` `json"…"` `legacy"…"` | текст с другой разметкой |
| `5` `-0.5` | число |
| `true` `false` | 1 и 0 |
| `loc(x, y, z)` `loc(x, y, z, yaw, pitch)` | местоположение, координаты — числа, переменные или формулы |
| `vec(x, y, z)` | вектор, так же |
| `item(diamond, 5)` | предмет |
| `block(composter)` | блок |
| `sound(entity.player.levelup, volume: 1, pitch: 2)` | звук |
| `particle(flame, count: 3)` | эффект частиц |
| `potion(speed, amplifier: 1, duration: 30s)` | зелье |
| `cell("данные")` `cell("данные", storage: "ник/хранилище", id: "uuid")` | ячейка хранилища: в файлах мира или в общем хранилище |
| `value.current_health` | игровое значение |
| `[1, 2, _]` | список |
| `{"a": 1, "b": 2}` | словарь |

Ячейка хранит переменные между перезапусками мира: `status = cell_save(cell("данные"), [score, coins])`, потом `cell_load`. У общего хранилища `storage` и `id` пишутся вместе, как в предмете ячейки: их проще всего взять из мира, прочитав код с такой ячейкой.

В тексте `\"` — кавычка, `\\` — обратная косая, `\n` — перенос строки, а `%player%` и другие [плейсхолдеры](docs/placeholders.md) работают как обычно.

В `mm"…"` закрывающий тег пишется так же, как открывающий: `<#ff8800>a</#ff8800>`, `<b>a</b>`. Другой, например `</color>` или `</bold>`, сервер оставит текстом.

### Предметы

```kotlin
when player_join {
    give_items(item(diamond_sword, name: "&bМеч героя", lore: ["Первая строка", "&6Вторая"],
        enchantments: {sharpness: 5, unbreaking: 3}, unbreakable: true, tags: {kind: "hero"}))
    give_items(item(paper, 2, name: mm"<gradient:#ff0000:#0000ff>Радуга</gradient>", glint: true))
    give_items(item(stick, damage: 3, model: 7, components: "{max_stack_size:1,rarity:'epic'}"))
}
```

| Поле | Что это |
|:--|:--|
| вторым по порядку или `count:` | количество, 1–99 |
| `name:` | имя, текст в любой разметке |
| `lore:` | описание: строка или список строк |
| `enchantments:` | чары, уровень 1–255 |
| `unbreakable:` | неразрушимый |
| `damage:` | сколько прочности потрачено |
| `glint:` | блеск чар: `true` всегда, `false` никогда |
| `model:` | число для ресурс-пака |
| `hide_tooltip:` | скрыть подсказку |
| `tags:` | кастомные теги JustMC |
| `components:` | остальные [компоненты](docs/components.md), как в `/give` |

`${…}` внутри `item(…)` не подставляется: имя предмета по ходу игры меняет действие `set_item_name`. Имя собирается заранее, поэтому `<click:…>`, `<hover:…>`, `<font:…>` и похожие теги в нём остаются текстом, компилятор об этом предупредит. Точный стек из игры — `item("H4sI…")`: так его копирует XeroCode, а `Ctrl+.` в VS Code расписывает его полями.

### Переменные

```kotlin
game round
save coins
save `монеты %player%`

when player_join {
    x = 1
    line t = 0
    round = 0
    coins += 10
    `монеты %player%` = 5
    a, b = value.current_health, value.food_level
}
```

| Область | Запись | Где живёт |
|:--|:--|:--|
| локальная | `x = 1` | одно срабатывание события или процесса, видна вызванным функциям |
| строчная | `line x = 1` | одна строка кода, у каждой строки своя |
| игровая | `game x = 1` | весь мир, пока он запущен |
| сохранённая | `save x = 1` | весь мир, остаётся после перезапуска |

- Первое присваивание объявляет переменную, слово области пишется один раз.
- Вне `when` область объявляют без значения: `save coins`. Так же объявляют переменную, которую задаёт другой код.
- Вид объявляют, если из кода его не понять: `save m: map`, `game l: list`. Тогда работает `m[k] = 1` с ключом в переменной.
- Чтение переменной, которую нигде не задают, — ошибка с подсказкой.
- `+=` `-=` `*=` `/=` `%=` — блоки сервера. `x = x + 1` собирается тем же блоком, что `x += 1`.
- Одно имя в разных областях — на месте: `game.x = 1`, `"${save.x}"`.

> 💡 Локальная не доживает до следующего события. Состояние игрока держи в игровой с ником в имени: `` game `держит %player%` ``.

### Постоянные

```kotlin
const MAX = 5
const SWORD = item(diamond_sword, name: "&bМеч")
const DEBUG = false

when player_join {
    give_items(SWORD, MAX)
    if DEBUG {
        send_message("вход")
    }
}
```

Значение подставляется при сборке, переменной на сервере нет. `if` с постоянным условием сворачивается: при `false` блоков не будет. Так же внутри `and`, `or` и `?:`: `if DEBUG and x > 0`.

Это то же, что `inline` в JMCC: на `inline X = …` сборка подскажет `const` и поправит по Ctrl+.

### Вызов от значения

```kotlin
const SWORD = item(diamond_sword, name: "&bМеч")

when player_join {
    give_items(SWORD.set_item_amount(10))
    rock = item(stone)
    rock.set_item_amount(5)
    give_items(rock.set_item_amount(2).set_item_lore(["&7камень"]))
    numbers = [3, 1, 2]
    numbers.sort_any_list()
    if numbers.list_contains_value(2) {
        send_message("есть")
    }
}
```

- `x.f(a)` — то же, что `f(x, a)`: значение слева встаёт первым аргументом после переменной результата. Цепочки читаются слева направо.
- Отдельной строкой `x.f(a)` записывает результат обратно: `x = f(x, a)`. Действия, которые сами меняют список или словарь, вызываются как есть.
- После точки редактор подсказывает действия и условия для этого вида значения.
- Если предмет — `const` и вызов записан через точку, сборка сворачивает действие в готовый предмет: `SWORD.set_item_amount(10)` уходит
  одним блоком, без временной переменной. Запись `set_item_amount(SWORD, 10)` остаётся действием: так код из мира и с полотна не меняется. Сворачиваются количество (1–99) и описание, если в каждой строке один стиль, — сервер делает такой же предмет байт в байт.
  Имя не сворачивается: сервер собирает его по-своему, и точное сравнение предметов разошлось бы.

### Формулы и подстановки

```kotlin
when player_jump {
    a, b = 2, 3
    x = a * 2 + b
    d = sqrt(a * a + b * b)
    hp = clamp(a - b, 0, 20) + 1
    send_message("Счёт: ${x}, разница ${a - b}, здоровье ${value.current_health}")
    send_message("цена \${x}")
}
```

- Вся формула — один блок: сервер считает её сам через `%math`.
- Функции: `abs` `sqrt` `cbrt` `ceil` `floor` `round` `pow` `min` `max` `sign` `atan2` `root` `clamp` `wrap` `asin` `acos`, `sin` `cos` в градусах, `sinr` `cosr` в радианах.
- Константы: `PI` `E`. Если есть переменная с таким именем, побеждает она.
- `${выражение}` в тексте — переменная, формула или значение. `\$` — буквальный доллар.
- `len(список)` — длина списка или словаря.
- Векторы — блоками: `a + b`, `a - b`, `a / b`, `a * 2`, `loc + vec`.
- Выражение читается слева направо: в `c + inc()` значение `c` берётся до вызова, даже если `inc` меняет `c`.
- `%` — остаток со знаком делимого, `round(2.5)` даёт 2: так считает сервер.

### Время

`5s` `1m30s` `500ms` `2h` `20t` `1d`, по-русски `5с` `1м30с` `2ч` `20т` `1д`.

```kotlin
when player_join {
    wait(5s)
    wait(2s, time_unit: seconds)
    give_potion_effect(potion(speed, duration: 30s))
}
```

Единицу задаёт аргумент: без подсказки это тики, `wait(5s)` — 100 тиков.

### Списки и словари

```kotlin
when player_join {
    l = [10, 20, 30]
    m = {"hp": 20}
    x = l[1]
    l[0] = 5
    l[2] += 1
    m["hp"] = m["hp"] - 5
    send_message("${l[0]} ${m["hp"]} всего ${len(l)}")
    g = [[1, 2], [3, 4]]
    g[1][0] = 9
}
```

Индекс — с нуля, чтение за границей списка даёт 0. Классов в языке нет: вместо них словари.

Несколько значений сразу — разложением:

```kotlin
when player_join {
    l = [10, 20, 30]
    m = {"hp": 20, "mana": 5}
    x, y, z = l[0, 1, 2]
    hp, mana = m["hp", "mana"]
    first, second = l
    send_message("${x} ${hp} ${second}")
}
```

`x, y = l[0, 1]` — один блок «Получить значения из списка», `hp, mana = m["hp", "mana"]` — «Получить значения словаря»,
`a, b = l` — «Разложить список». Несколько индексов бывают только в разложении: `x = l[0, 1]` — ошибка.

Значения в литерале могут быть любыми. Сервер не считает то, что лежит внутри готового списка, поэтому `[a, 2]` и `{"k": a}` с переменной собираются блоком создания:

```kotlin
when player_join {
    a = 5
    l = [a, 2]
    m = {"k": a, "n": a + 1}
    send_message("${l[0]} ${m["n"]}")
}
```

Значение как есть, без блока, — `literal([a, 2])`: внутри окажется сама переменная, а не её значение.

### Условия

```kotlin
when player_join {
    coins = 100
    if coins >= 100 {
        send_message("Богач")
    } else if not coins > 0 {
        send_message("Пусто")
    } else {
        send_message("Есть немного")
    }

    if is_sneaking() and coins > 5 or has_item(item(diamond)) {
        send_message("Да")
    }

    ok = coins > 3
    if ok {
        send_message("Больше трёх")
    }
    big = coins > 3 ? "да" : "нет"
}
```

- Сравнение: `==` `!=` `>` `>=` `<` `<=`. Логика: `and` `or` `not` и скобки в любых сочетаниях.
- Проверка — условие сервера по имени: `has_item`, `is_sneaking`.
- `условие ? да : нет` — выбор значения. `ok = условие` записывает 1 или 0.
- `if ok` — то же, что `ok == 1`. Так же пишутся `if is_ready()` с функцией из файла и `if flags[0]` с клеткой списка.
- В блоках «Выбрать … по условию» `and` и `or` нельзя.

Проверка на вхождение:

```kotlin
when player_join {
    x = 2
    l = [1, 2]
    stats = {"hp": 20}
    if x in [1, 2, 3] { }
    if x in 1..5 { }
    if x in l { }
    if "hp" in stats { }
    if x not in l { }
}
```

`x in 1..5` включает оба конца. `x == 1 or x == 2` собирается в один блок, как `x in [1, 2]`.

Сравнения разных переменных тоже собираются в один блок «Равны»: `a == 1 and b == 2` — режим «Все переменные»,
`a == 1 or b == 2` — «Любая переменная», а `a != 1 and b != 2` — «Равны» с «НЕ». Справа — число, текст или переменная, пар до 20.
В «Выбрать … по условию» такая цепочка тоже годится: это одно условие.

### Повторения

```kotlin
when player_join {
    l = [1, 2]
    m = {"a": 1}
    x = 0
    repeat 10 { }
    for i in 1..10 { }
    for i in 0..100 step 5 { }
    for v in l { }
    for i, v in l { }
    for k: v in m { }
    while x < 5 {
        x += 1
        if x == 3 {
            continue
        }
    }
    forever {
        wait(20)
        break
    }
}
```

Конец диапазона включается, индекс в списке — с нуля. Остальные повторения — действием с телом: `repeat.on_sphere(…) { }`.

### Импорт и модули

```kotlin
import "kits.xero"
import "mapi"
import "mapi" connect
```

| Запись | Что делает |
|:--|:--|
| `import "kits.xero"` | файл проекта, путь от текущего файла |
| `import "mapi"` | модуль JustMC: имя, название или id. Код уходит в мир вместе с проектом |
| `import "mapi" connect` | модуль подключается через `/module`, код в проект не идёт. Нужен мод XeroCode |

- `xero build папка/` собирает все `.xero` в папке одним модулем: переменные и функции видны во всех файлах.
- Функции модуля вызываются как свои: `Mapi.about2()`, `start Mapi.tick()`.
- Код модуля скачивается один раз в `.xero/modules/`. Свежая версия — `xero module update`.
- Одно имя бывает у разных авторов: возьмётся самый установленный, а сборка предупредит. Другой выбирают по id, список — `xero module find имя`.
- Платный модуль покупают в игре через `/module`.

### Пометки

```kotlin
@display_description("Первая строка описания", "Вторая строка")
@icon(item(iron_ingot))
@hidden
func `WE Load`() { }

@line(10)
when player_join { }
```

| Пометка | Что делает |
|:--|:--|
| `@hidden` | скрыть функцию в меню вызова |
| `@icon(…)` | значок |
| `@display_name(…)` `@display_description(…)` | имя и описание, каждая строка — с новой |
| `@description(…)` | описание старого вида, по строке на клетку |
| `@line(N)` | поставить строку на номер `N`, следующие пойдут за ней |
| `@custom_data("текст")` | свой текст строки, до 256 символов; бывает и у `when` |

Строки в `/dev` нумеруются с нуля, по 35 на этаж. Номера идут только вперёд.

### Особые формы

| Запись | Что это |
|:--|:--|
| `_` отдельной командой | пустой блок в строке |
| `num("%math(%var(x)+1)")` | число, записанное текстом |
| `call(имя, аргумент: значение)` | вызов функции, имя которой — значение |
| `start call(имя, аргумент: значение)` | запуск процесса, имя которого — значение |
| `literal([a, 2])` `literal({"k": a})` | список или словарь как есть, без блока создания |
| `literal(x + 1)` | значение как есть: аргумент вызова не считается заранее |
| `enum("ERROR")` | вариант настройки, которого нет в данных |
| `raw("{…JSON…}")` | значение или блок как есть |

## Заливка в мир

Сервер не принимает строку шире 67 блоков. Xero переносит лишнее в скрытые функции `<имя строки>.N` сам: `return`, `break`, `continue` и
`else` работают как написаны. Если перенести нельзя, сборка предупредит.

| Как | Что происходит |
|:--|:--|
| **Залить** | код мира заменяется проектом: `/module load-url force …` |
| **Дописать** | код ложится в свободные строки: `/module load-url …`, ничего не стирается |
| **Сразу в игру** | с модом XeroCode: без буфера обмена и команды в чате |

Команду вставляют в чат в `/dev` в течение 60 секунд: ссылка одноразовая. Код уходит в хранилище Xero, а если оно не ответило — на `m.justmc.ru`, и тогда ссылка живёт около минуты.

**Защита от стирания.** Xero помнит последнюю копию мира в `.xero/world.json`. Если в ней есть строки, которых нет в проекте, заливка откажет и покажет их. Стереть их нарочно — `--drop`. Строки без правок уходят в мир ровно такими, какими были.

**Правки из `/dev`** Xero сам не видит. Забрать их можно до заливки: в `/dev` набери `/editor download`, скопируй ссылку (нужен ранг Meteor+).

```bash
xero pull <ссылка>                      # код мира → world.xero и копия мира
xero upload main.xero --world <ссылка>  # или сразу перед заливкой
xero diff main.xero                     # что изменится, ничего не меняя
```

**Задвоение.** При дописывании Xero откажет, если функция с таким именем уже есть в мире: сервер не заменил бы её, а задвоил. Залить всё равно — `--duplicate`.

**Сразу в игру.** Мод XeroCode открывает локальный порт. Игрок должен быть в `/dev`.

```bash
xero upload main.xero --game    # залить через игру
xero pull --game                # код мира из игры: без ссылки и без ранга
```

Книгу подтверждения мод принимает сам, открытое окно при этом не закрывается. «Залито» появляется только после ответа сервера. Если сервер не смог забрать код, мод повторит заливку через `m.justmc.ru`, а если просит подождать — повторит команду сам. Отказ сервера показывается как есть, и копия мира при этом не меняется.

**Код из мира** превращается в обычный `.xero`, и `xero build` собирает его обратно в тот же код. Незнакомое печатается через `raw(…)`, поэтому ничего не теряется. Пустые слоты и маркеры со значением по умолчанию не печатаются, числа и формулы читаются как обычные выражения, а предмет — полями, если это надёжно, иначе `item("H4sI…")`. Аргумент, который сервер не считает заранее, печатается `literal(…)`. Сверка считает такой код тем же и строки не переливает.

**Своё хранилище:**

```bash
xero upload main.xero --store http://1.2.3.4:8791/xerocode/
```

То же — переменная `XERO_STORE` или настройка `xero.storeUrl`. Адрес лучше давать как у хранилища Xero: голый `http://` с IP.

## Проверки

**Правило:** что сервер останавливает с ошибкой — ошибка сборки. Что принимает впустую — предупреждение.

| Что проверяется | Пример |
|:--|:--|
| Имена | опечатка в действии, цели, настройке: «возможно, вы имели в виду …» |
| Переменные | `scroe` нигде не задана. Возможно, `score` |
| Виды значений | `player.teleport(5)`: нужно местоположение, передано число |
| Порядок аргументов | у `block_equals` сначала идёт `blocks`, потом `location` |
| Id | предметы и блоки — Minecraft 26.2, остальное — данные сервера |
| Текст | скобки, функции и число аргументов в `%math(…)` |
| События | действие над игроком в событии мира без цели, `cancel_event()` там, где отменять нельзя |
| Локальные | переменная задана в одном событии, а читается в другом |
| Мёртвый код | переменная не читается, параметр не используется, код после `return` |
| Числа | `item(diamond, 5.5)`, деление на постоянный ноль |

Ошибки показываются все сразу, код выхода — 1. `xero build --json` отдаёт их списком вместе с готовыми правками.
